# ADR-0003：需求分析后必须人工批准

- 状态：已接受，交互方式由 D-011 修正
- 日期：2026-09-15

## 背景

需求分析 Agent 使用 grill 类方法澄清需求并生成文档。如果分析结果未经用户确认就进入实现，Agent 的错误推断、范围扩张或遗漏会直接转化为代码修改，并在后续阶段放大成本。

## 决策

1. Requirement Analyst 仅执行需求澄清、分析和文档生成。
2. Requirement Analyst 不承担实现职责，也不能启动实现 Agent。
3. 分析结束后 Run 必须进入 `WAITING_FOR_REQUIREMENT_APPROVAL`。
4. 只有用户可以批准需求。
5. 用户退回时创建新的分析 Attempt，保留旧版本，不覆盖历史。
6. 在批准前，Orchestrator 不得调度任何写入型实现阶段。

## 后果

正面：

- 用户对范围和验收条件拥有最终控制权；
- 降低错误需求直接进入实现的风险；
- 需求版本和退回历史可追踪；
- 后续测试和审查可以引用已批准的验收条件。

负面：

- 全流程不再默认无人值守；
- 用户必须完成一次明确审批；
- UI 需要实现等待审批、文档 diff、批准和退回交互。

## 后续问题

- 实施计划后是否还需要第二个人工审批门；
- 是否在未来提供用户显式开启的自动审批策略。

## D-011 交互修正

需求批准不一定表现为单独的“是否开始编码”弹窗。需求分析 Agent 完成并停止后，用户手动切换到 Coding Agent、确认或发送“读取交接文档并编写代码”，该动作即为显式推进和批准。系统不会自动启动 Coding Agent。
