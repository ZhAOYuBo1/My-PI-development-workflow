# Proposal

## Why

模型选择和思考强度现在挤在同一个弹窗里，两者其实是两个不同频率的操作：

- **模型**是低频决定 —— 换模型意味着换供应商、换上下文窗口、换计费，通常一个 Agent 整个生命周期就换一两次。
- **思考强度**是高频微调 —— 简单任务调低省时间和 token，复杂任务调高换质量，往往一条消息里就要来回切好几次。

把高频操作藏在低频弹窗里，等于每次微调都要「打开 → 找到那排按钮 → 点一下 → 关掉」，而打开弹窗这个动作本身还会遮挡整屏。加上模型座位按钮上写着 `模型名 · 强度`，用户在**不打开任何东西**的情况下就已经能看到强度当前值 —— 也就是说这个值本来就常驻可见，那么把它做成可点的控件才是一致的。

具体到界面：`App.tsx:4742-4754` 在搜索框下面塞了一排 `.thinking-row` 按钮，位置在「选择模型」标题之下、模型列表之上，视觉上像是模型列表的一个筛选器，但它改的其实是另一个维度。用户看标题进来 expecting 选模型，却被一排无关控件挡了一下。

## What Changes

- **模型弹窗只负责选模型**：移除 `.thinking-row` 整块；搜索框之下直接是按供应商分组的模型列表。
- **思考强度成为输入区常驻控件**：放在发送按钮左侧，与发送按钮同一组右对齐。形态是一条**横向分段状态条**，选中段的底色块在切换时左右滑动过渡，而不是每个按钮各自独立变色。
- **模型座位按钮只显示模型名**：去掉 ` · {强度}` 后缀，强度改由新控件自己承担展示。
- **`/thinking` 不再打开模型弹窗**：带参数仍直接切换；不带参数改为在当前强度上循环下一档，并在转录流里留下一条系统提示说明切到了哪一档。

## Capabilities

### New Capabilities

- `desktop-thinking-control`：输入区思考强度分段控件的位置、形态、滑动指示器、键盘操作、窄窗降级与空态处理。

### Modified Capabilities

- `desktop-model-picker`：模型选择弹窗的职责收窄为「只选模型」，不再承载思考强度。

## Impact

- 仅影响 `packages/codpiddy-desktop/src/renderer/`：`App.tsx`（弹窗去掉强度行、工具栏加控件、`/thinking` 分支）、`styles.css`（新增分段控件样式，删除 `.thinking-row` 三条规则）。
- **不改任何后端契约**：`setAgentThinking` / `AgentModelSelection` / `availableThinkingLevels` 全部已存在且已在用（`App.tsx:3452` 的 `chooseThinking`），本次只是换一个调用入口。
- 不改权限、Skill、工作面板等其他设置或转录流行为。
